### 1.3 Rules inside the skills that matter most for output quality

Animation and timing (`remotion-markup/SKILL.md`, `timing.md`):
- Drive ALL motion from `useCurrentFrame()` + `interpolate()`. "CSS `transition` or `animation` will not render correctly"; Tailwind `animate-*`/`transition-*` classes are banned (`remotion-create/tailwind.md`). Three.js: `useFrame()` is forbidden, anything self-animating "will cause flickering during rendering" (`3d.md`).
- Always clamp (`extrapolateLeft/Right: 'clamp'`); unclamped interpolate overshoots.
- Customise timing with `Easing.bezier(...)` (house example `Easing.bezier(0.16, 1, 0.3, 1)`, an expo-out) or `Easing.spring({damping: 200})` ("a nice push movement with no bounce").
- For scale animations add `output: 'perceptual-scale'` ("if the output is linear, the perceived scale would be smaller the larger the scale gets").
- Multi-keyframe `interpolate` takes an easing array of length n-1. `posterize: n` for a deliberate low-frame-rate look.
- Use the individual CSS `scale` / `translate` / `rotate` properties, not `transform` strings (Studio editability; `transform` only for skew/perspective/order-sensitive chains).
- Get `fps` from `useVideoConfig()` and write timing as `2 * fps` on the JSX node; never a hard-coded FPS constant.
- Performance: keep `useCurrentFrame()` in the smallest component that needs it, otherwise "unrelated descendants re-render on every frame".

Layout and typography (`remotion-create/video-layout.md`):
- "You are designing a video, not a webpage." Decide the one thing the viewer notices first per scene.
- Safe area for 1080-wide: key text >= 80px from the sides, >= 100px from top/bottom. Minimum sizes at 1080 wide: headline 84px, supporting text 44px. "Do not add redundant elements."
- Fonts: Google Fonts via `@remotion/google-fonts/<Family>` (blocks rendering until loaded; load only needed weights/subsets); local fonts via `@remotion/fonts` `loadFont({family, url: staticFile(...), weight})`, one call per weight.
- Text fitting via `@remotion/layout-utils` (`measureText`, `fitText`, `fillTextBox`); measure only after the font has loaded (`waitUntilDone()`, `validateFontIsLoaded: true`); use `outline` not `border` so the measured box equals the rendered box.

Media (`embedding-videos.md`, `audio.md`, `video-editing.md`, `ffmpeg.md`):
- `<Video>` / `<Audio>` from `@remotion/media`; images via `<Img>` / `<CanvasImage>`; assets in `public/` via `staticFile()`.
- Trim non-destructively with `trimBefore` + `durationInFrames`. If you must cut with ffmpeg, "You MUST re-encode the video to avoid frozen frames at the start".
- Keep a shot's video, captions and synced overlays under ONE timing boundary (a `Sequence` / `TransitionSeries.Sequence`) so trims/speed apply to all layers. "Putting captions inside a scene is insufficient if trimBefore or playbackRate is still applied only to `<Video>`."
- Audio: `toneFrequency` only works in server render, not Studio preview. Do not shorten sound effects to fit; overlapping tails need separate tracks.
- `npx remotion ffmpeg` / `npx remotion ffprobe` are bundled, no system ffmpeg needed.

Scenes and transitions (`transitions.md`, `multi-scene-video.md`):
- `TransitionSeries` with `.Sequence`, `.Transition` (fade, slide, wipe, flip, clockWipe; `linearTiming`/`springTiming`) and `.Overlay` (e.g. light leak at the cut; does not shorten the timeline). Transitions shorten the total: total = sum(scenes) - sum(transitions); compute it with `timing.getDurationInFrames({fps})`.

Captions (`remotion-captions/*`): captions are `Caption[]` JSON; include the leading space in each word's `text` ("The captions are whitespace sensitive"); timestamps stay relative to the SOURCE file; recommended display = copy the "Basic Captions" element source (https://www.remotion.dev/elements/captions/basic-captions.md) unchanged.

Workflow rules:
- "Preserve user changes": if code changed outside the conversation, assume it was intentional.
- Open Studio first and keep it open; "Don't render the video by default unless they are very explicit."
- Install Remotion packages with `npx remotion add <pkg>` so versions match (also for `zod`, `mediabunny`, `@huggingface/transformers`).
- Visual checks: Studio, or render specific frames: `npx remotion render <id> out/frames --frames=0,30,90 --image-format=png`.

Tension to resolve for our studio: many skill rules optimise for **hand-editing in Studio** (inline `defaultProps` object literal, inline caption arrays on the node, `Interactive.*` wrappers, "do not store defaultProps in a variable"). The skills themselves allow the alternative: "Programmatic registration is suitable when the generated compositions are intentionally controlled as one source template" (`compositions.md`). A data-driven template rendering fault-code x language variants is exactly that case, so we follow the motion/media/layout rules but NOT the Studio-editability rules for captions/props (captions come from a JSON file per variant, props from zod-validated data).

### 2.3 Folder layout for a multi-composition, data-driven project

The docs only prescribe `src/index.ts` (`registerRoot`), `src/Root.tsx` (compositions), `public/` (assets via `staticFile()`), `remotion.config.ts` (CLI/Studio only) (https://www.remotion.dev/system-prompt.txt). Everything else is our choice; see "Decisions" for the proposed tree. Relevant rules:
- `<Folder name="...">` groups compositions in the Studio sidebar (letters, numbers, hyphens only) (`compositions.md` in skills).
- Register ONE template composition per format (e.g. `Scenario-9x16`) with a zod `schema` and `calculateMetadata`; variants are input props, not separate compositions. The skills say programmatic registration is fine "when the generated compositions are intentionally controlled as one source template".
- `defaultProps` must be JSON-serialisable; use `type` not `interface` for props.

### 2.4 zod-typed props

- `schema={MySchema}` on `<Composition>`; top level must be `z.object()`; Studio then shows editable props in the sidebar; `zColor()` from `@remotion/zod-types` gives a colour picker (`parameters.md` in skills; https://www.remotion.dev/docs/schemas). Use zod 4.5.4 (the version `@remotion/studio` pins).
- Pass variant props at render time with `--props=./variants/p0420.de.json` (CLI) or `inputProps` (`selectComposition` + `renderMedia`). Note: `remotion.config.ts` "doesn't apply" to the Node APIs; pass every option explicitly there (comment in template remotion.config.ts).

### 2.5 `calculateMetadata` (duration from audio)

- Runs before render (and in Studio); may return `durationInFrames`, `fps`, `width`, `height`, transformed `props`, `defaultOutName`, `defaultCodec` (and `defaultPixelFormat`, `defaultVideoImageFormat`, `defaultProResProfile`, per `transparent-videos.md`). It gets an `abortSignal` for fetches (https://www.remotion.dev/docs/dynamic-metadata; skills `calculate-metadata.md`).
- Voiceover recipe from the skills (`voiceover.md`): generate one MP3 per scene into `public/voiceover/<comp>/<scene>.mp3` with ElevenLabs, then in `calculateMetadata` sum `getAudioDuration()` (Mediabunny `Input(...).computeDuration()`) x fps, `Math.ceil`, and pass per-scene durations into props. If using `TransitionSeries`, subtract transition overlaps. `calculateMetadata` cannot call `useVideoConfig()`.
- Better for us: compute durations in the build script from the ElevenLabs alignment JSON (exact end time of last character) and write them into the props JSON, so `calculateMetadata` only reads props. Avoids decoding audio in the browser and keeps the timeline reproducible.
- Known fixed bug: `getCompositions()` could crash the process when `calculateMetadata()` throws (issue #11679, closed 2026-09-26). Still: validate props with zod BEFORE rendering so a bad variant fails fast.

### 2.6 Studio preview workflow

- `npm run dev` = `remotion studio`. Skills: open Studio first and keep it open while editing; `npx remotion studio --no-open` prints the URL; `/<composition-id>` deep-links a composition (`remotion-best-practices`, `remotion-studio`). Studio premounts items 2 s by default since 4.0.535 (https://www.remotion.dev/docs/player/premounting).
- Studio has a Render dialog (all codec/quality options) and props editor; WebMCP agent tools exist but Claude Code cannot use them yet (section 1).
- Open bug to know about: Studio preview shows a 1px seam under a bottom letterbox bar at fractional zoom; "render is correct" (issue #12461, open 2026-10-21). Judge pixel details on rendered stills, not on Studio.

### 2.7 Rendering from scripts: CLI vs `@remotion/renderer`

- CLI: `npx remotion render <id> out/x.mp4 --props=props.json [flags]`; `npx remotion still <id> out/x.png --frame=N`; `npx remotion render <id> out/frames --frames=0,30,90 --image-format=png` for several QA frames in one call (`remotion-render` skill; https://www.remotion.dev/docs/cli/render).
- Node API: `bundle()` once (reuse the bundle for all variants; "Calling bundle() for every video that you render is an anti-pattern"), then per variant `selectComposition({serveUrl, id, inputProps})` + `renderMedia({composition, serveUrl, codec, outputLocation, inputProps, ...})`. `openBrowser()` shares one Chrome across renders (https://www.remotion.dev/docs/ssr-node, https://www.remotion.dev/docs/bundle).
- For a batch of fault-code x language variants, the Node API is the better fit (one bundle, one browser, progress callbacks, typed options). License note: both the CLI from a script and `renderMedia()` count as "automation" under the v5 terms, which only matters if we stop qualifying for the Free License (section 7).

## 3. Embedding screen recordings

### 3.1 Which tag

- "For new code, use `<Video />` from `@remotion/media`. It is the recommended component" (https://www.remotion.dev/docs/video-tags). Comparison table on that page: `@remotion/media` `<Video>` = Mediabunny + WebCodecs, frame-perfect, partial download, **fastest** render; `<OffthreadVideo>` = Rust + FFmpeg, frame-perfect, fast; `<Html5Video>` (the old `<Video>` from `remotion`) = not frame-perfect.
- **Codec support is the trap:** `@remotion/media` decodes AAC, FLAC, H.264, MP3, Opus, VP8, VP9, Vorbis. H.265/HEVC is NOT in the list; "The codec cannot be decoded by WebCodecs (e.g. a H.265 stream during rendering)" triggers a silent-ish fallback to `<OffthreadVideo>` with only a log line "Cannot decode ..., falling back to <OffthreadVideo>" (https://www.remotion.dev/docs/media/fallback). iOS Simulator `simctl io recordVideo` defaults to HEVC on recent Xcode (verify in the simulator research file), so transcode or record H.264.
- Set `disallowFallbackToOffthreadVideo` on every `<Video>` in the studio so an unsupported input FAILS the render instead of quietly switching engines (https://www.remotion.dev/docs/media/video#disallowfallbacktooffthreadvideo).
- ProRes input works with `<Video>` only after `npx remotion add @mediabunny/prores` and `registerProresDecoder()` in `src/index.ts` (from 4.0.487); slower without cross-origin isolation (https://www.remotion.dev/docs/videos/prores).
- Useful props: `objectFit` ('contain' default, 'cover', ...; CSS `object-fit` is NOT supported) (4.0.442), `cropLeft/Right/Top/Bottom` ratios (4.0.500), `from`, `trimBefore`, `durationInFrames` (`trimAfter` is deprecated, PR #11685), `playbackRate` (pitch now follows speed by default; `preservePitch` from 4.0.538), `premountFor`/`postmountFor` (4.0.495), `effects` (4.0.464), `maxCanvasSinkFrameSize` (preview memory only), `muted`, `volume` (https://www.remotion.dev/docs/media/video).

### 3.2 Variable frame rate (screen recordings)

- Docs: VFR "is most common for screen recordings, where a frame is only sampled when the content has changed"; "Remotion and most other video editors do not support variable frame rate timelines or outputting variable frame rate videos. You must specify a constant frame rate for your composition." Use Mediabunny `computeFrameRateMetrics()` (`frameRateIsConstant`, `bestGuessFrameRate`, `underlyingFrameRate`, `maxFrameRate`); "Don't use the average frame rate" (https://www.remotion.dev/docs/mediabunny/frame-rate).
- `<Video>` seeks by timestamp ("extracts the exact frame ... keeps the video in sync with Remotion's timeline", https://www.remotion.dev/docs/media/video), so a VFR source plays at the right wall-clock time, but frames that were never written are held, and timing of a tap relative to our JSON tap timeline depends on the recording's timestamps being trustworthy.
- Old guidance (still valid as a remedy): corrupted/odd H.264 timestamps that break seeking are fixed by re-encoding, `npx remotion ffmpeg -i in.mp4 out.mp4` (https://www.remotion.dev/docs/slow-method-to-extract-frame). If cutting with ffmpeg: "You MUST re-encode the video to avoid frozen frames at the start" (skills `ffmpeg.md`).
- **Our normalisation step (recommendation):** every simulator recording goes through ffmpeg once before entering `public/`: constant 60 fps (or 30), H.264 High, `yuv420p`, bt709 tags, short GOP (e.g. `-g 30` or all-intra for heavy scrubbing), `+faststart`, audio stripped. Keep the original for timestamp mapping: the tap-timeline JSON must be re-based onto the normalised file's t=0 (the simulator recording start is not the integration-test start).

### 3.3 Recommended input format for recordings

- Studio preview + render both decode with WebCodecs, so **H.264 CFR in MP4** is the native, fastest path. ProRes needs an extra decoder package and is "slower" without cross-origin isolation; HEVC falls back to OffthreadVideo. Use high bitrate / low CRF (e.g. `-crf 12 -preset slow`) for intermediates; disk is cheap and UI text must stay crisp after the final social re-encode.
- Shorter keyframe interval = faster, more reliable scrubbing in Studio. Remotion exposes `--gop` for its own OUTPUT (4.0.466, https://www.remotion.dev/docs/options/gop); for inputs, set `-g` in our ffmpeg normalisation.

### 3.4 Audio components

- `<Audio>` from `@remotion/media` (falls back to `<Html5Audio>` for unsupported media; `disallowFallbackToHtml5Audio` to forbid). Props: `from`, `trimBefore`, `durationInFrames`, `volume` (number; use `interpolate` for envelopes; the callback form is "no longer recommended"), `loop`, `playbackRate`, `toneFrequency`, `muted` (can be frame-dependent) (skills `audio.md`; https://www.remotion.dev/docs/media/audio).
- Output sample rate defaults to 48000 Hz; "Match this to your source audio to avoid resampling artifacts" (`--sample-rate`, 4.0.448, https://www.remotion.dev/docs/options/sample-rate). ElevenLabs output formats include 44.1 kHz MP3 by default: request a 48 kHz format or resample once in the pipeline.

### 3.5 Sequence / Series / TransitionSeries / Track / premounting

- Timing props now sit directly on `<Video>`, `<Audio>`, `<Img>`, `<AbsoluteFill>`, `Interactive.*`, `<Sequence>`, `<Track>`; order of operations `from` -> `trimBefore` -> `durationInFrames` -> `playbackRate` -> `loop`; child frame = `trimBefore + (frame - from) * playbackRate` (skills `timing-props.md`; https://www.remotion.dev/docs/timing).
- Choose the boundary: `<Series>` / `TransitionSeries` for back-to-back scenes that should reflow when a duration changes; `<Track>` for non-overlapping items with independent start times; a shared `<Sequence>` (`layout="none"` for no wrapper) when several layers must share one trim/speed (skills `sequencing.md`, `multi-scene-video.md`).
- Premounting is preview-only ("has no effect during rendering"); Studio premounts 2 s by default since 4.0.535; Player does not until Remotion 5 (https://www.remotion.dev/docs/player/premounting). So it fixes Studio stutter, not render bugs.
- Flicker rules (https://www.remotion.dev/docs/flickering): Remotion renders frames in parallel tabs; components must be pure functions of the frame (same output every call, no reliance on render order, no `Math.random()` except `random(seed)`). `--concurrency=1` "does not fully fix the problem". Wait for assets: media tags and `<Img>` block automatically; data needs `delayRender()`/`useDelayRender()`; avoid CSS `background-image` / `mask-image`.

## 4. Captions

### 4.1 `@remotion/captions` (since 4.0.216)

- Central type (https://www.remotion.dev/docs/captions/caption, skills `remotion-captions/SKILL.md`):
  ```ts
  type Caption = { text: string; startMs: number; endMs: number; timestampMs: number | null; confidence: number | null; pageBreakAfter?: boolean };
  ```
- `text` is whitespace-sensitive: put the space BEFORE each word (`" world"`); render the container with `white-space: pre`. Omitting spaces "will cause the entire text to merge into a single line or page" (https://www.remotion.dev/docs/captions/create-tiktok-style-captions).
- `createTikTokStyleCaptions({captions, combineTokensWithinMilliseconds, breakOnSilenceAfterMilliseconds?})` -> `{pages}`; each `TikTokPage` = `{text, startMs, durationMs, tokens: [{text, fromMs, toMs, pageBreakAfter}]}`. `breakOnSilenceAfterMilliseconds` (4.0.514) starts a new page at a pause; `pageBreakAfter: true` on a Caption forces a page end (4.0.517). Same page. We should drive page breaks from the SCRIPT (sentence/clause ends) via `pageBreakAfter`, not only from timing, so line breaks are linguistically sane in 14 languages.
- Other helpers: `parseSrt()` / `serializeSrt()` (for exporting .srt to upload as platform captions).
- Ready-made display components are "Elements" (copy-paste source): Basic Captions (recommended by the skills, copy `basic-captions.tsx` unchanged), Word Highlight Captions, Rounded Captions (https://www.remotion.dev/elements/captions). Use as a reference only; design our own caption style (see Decisions).
- Sources that convert to `Caption`: `@remotion/install-whisper-cpp` `toCaptions()`, `@remotion/whisper-web`, `@remotion/whisper-webgpu` (4.0.518), `@remotion/openai-whisper` `openAiWhisperApiToCaptions()`, `@remotion/elevenlabs` `elevenLabsTranscriptToCaptions()` (4.0.443) (https://www.remotion.dev/docs/captions/api).

### 4.2 ElevenLabs character timestamps -> `Caption[]`

- `@remotion/elevenlabs` only converts **Speech-to-Text (Scribe)** output (a `words` array with `type: "word" | "spacing" | "audio_event"`) or the segmented JSON export; it does NOT take the TTS character alignment (https://www.remotion.dev/docs/elevenlabs/elevenlabs-transcript-to-captions). So for TTS we write a ~40-line converter.
- TTS with timestamps: `POST /v1/text-to-speech/{voice_id}/with-timestamps` returns `audio_base64`, `alignment` and `normalized_alignment`, each `{characters[], character_start_times_seconds[], character_end_times_seconds[]}`; `output_format` default `mp3_44100_128`, 48 kHz options are `pcm_48000`, `wav_48000`, `opus_48000_*`; `apply_text_normalization` `auto|on|off` (https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps, fetched 2026-10-26). Details belong to the ElevenLabs research file.
- Converter algorithm (ours): walk `alignment.characters`; start a new word at a non-space char that follows whitespace; word `startMs = first char start * 1000`, `endMs = last non-space char end * 1000`; `text = (index > 0 ? ' ' : '') + word`; `timestampMs = (start+end)/2`; `confidence = null`; set `pageBreakAfter` where the script marks a break (`.`, `?`, `!`, or an explicit `|` marker stripped before TTS). Use `alignment` (original text), not `normalized_alignment`, because the normalized one spells out "P0420" as words and would show "P zero four two zero" on screen. If text normalisation makes `alignment` drift, synthesise the code as we want it spoken (e.g. "P zero four twenty") and keep a separate display string for the on-screen code chip, not in the captions.
- If the voiceover is generated per scene (one request per scene, as the skills recommend), offset each scene's captions by that scene's start in the timeline, OR keep captions inside the scene's `<Sequence>` so they stay relative to their own audio file (the skills prefer the latter: "Keep the resulting caption timestamps relative to the beginning of that source file").

### 4.3 Aligning a HUMAN recording

Options, best first for our case (known script, 14 languages):
1. **ElevenLabs Forced Alignment** (we already pay for ElevenLabs): `POST /v1/forced-alignment`, multipart `file` + `text`, returns `characters[{text,start,end}]`, `words[{text,start,end,loss}]` and a top-level `loss` (https://elevenlabs.io/docs/api-reference/forced-alignment/create). Since we know the exact script, alignment beats transcription (no misheard words in captions). Map `words` -> `Caption` the same way (prefix spaces). Language coverage not stated on the page; verify per locale.
2. **`@remotion/install-whisper-cpp`** (since 4.0.115): installs whisper.cpp + model locally; `transcribe({tokenLevelTimestamps: true, ...})` passes `--dtw` and returns `t_dtw` ("Prefer relying on the `t_dtw` value for accurate timestamps over `offsets`"); `splitOnWord`, `language`, `flashAttention` options; input must be 16 kHz WAV (`npx remotion ffmpeg -i in -ar 16000 out.wav`) (https://www.remotion.dev/docs/install-whisper-cpp, https://www.remotion.dev/docs/install-whisper-cpp/transcribe). The docs example pins whisper.cpp 1.5.5; the TikTok template uses 1.6.0 with `medium.en`; large-v3-turbo needs >= 1.7.2 (template `whisper-config.mjs`). For non-English use a multilingual model (drop `.en`).
3. **`@remotion/whisper-webgpu`** (since 4.0.518, what the current skills recommend): Transformers.js + WebGPU in Node or browser, `small`/`small.en` default, `language` REQUIRED for multilingual models ("automatic language detection is not supported"), "A compatible GPU is required" (`canUseWhisperWebGpu()`), models mirrored on remotion.media (https://www.remotion.dev/docs/whisper-webgpu, skills `transcribe-captions.md`). Newer and less battle-tested than whisper.cpp; fine for a quick pass.
4. `@remotion/openai-whisper` for the hosted OpenAI API (`openAiWhisperApiToCaptions()`).

Whichever path: captions are DATA (a JSON file per variant and language), human-checked once, never regenerated silently at render time.

## 5. Motion quality

### 5.1 spring / interpolate / easing

- `interpolate(frame, inputRange, outputRange, {easing, extrapolateLeft, extrapolateRight, output, posterize})`. Output ranges can be CSS strings for `scale`/`translate`/`rotate`/`transformOrigin` (4.0.472). `output: 'perceptual-scale'` (4.0.490) makes the visible AREA change linearly ("additive interpolation changes the CSS number linearly, but the visible area changes with `scale ** 2`"); "`easing` still controls time and progress. `output` controls the value distribution after easing." (https://www.remotion.dev/docs/interpolate). Use it for every zoom/scale-in, including push-ins on the phone recording.
- `Easing.spring({damping: 200})` as an interpolate easing = critically damped push, no bounce; `Easing.bezier(0.16, 1, 0.3, 1)` is the skills' default ease-out (skills `timing.md`).
- `spring({frame, fps, config: {mass=1, damping=10, stiffness=100, overshootClamping=false}, durationInFrames, durationRestThreshold, delay, reverse})`. "To disable the default bounce, increase the damping parameter." Defaults bounce visibly: an un-tuned `spring()` is one of the stock "Remotion demo" looks (https://www.remotion.dev/docs/spring). Always pass `fps` from `useVideoConfig()`, and `durationInFrames`/`delay` in `* fps` units so 30 vs 60 fps renders look the same (https://www.remotion.dev/docs/multiple-fps). `measureSpring()` gives a spring's natural length.
- Frame-rate independence: write timings as `n * fps`; the old FPS-convert snippet "is not recommended because it does not work with media tags" (https://www.remotion.dev/docs/multiple-fps).
- Our web repo already has a motion standard (Emil Kowalski / apple-design skills, CLAUDE.md "Design and motion"); port the spirit (ease-out for entrances, short durations, springs critically damped for UI, no bounce on informational UI) into the studio's motion tokens as named easing + duration constants, so every scene uses the same 3-4 curves.

### 5.2 `@remotion/transitions`

- `TransitionSeries` with `.Sequence`, `.Transition` (`presentation` + `timing`: `linearTiming({durationInFrames})` or `springTiming({config, durationInFrames})`) and `.Overlay` (an effect at the cut that does not shorten the timeline) (skills `transitions.md`; https://www.remotion.dev/docs/transitions).
- Presentations in `packages/transitions/src/presentations` on main (2026-10-26): blur-slide, book-flip, clock-wipe, cross-zoom, crosswarp, dissolve, dreamy-zoom, fade, film-burn, flip, iris, linear-blur, none, push-cut, ripple, slide, swap, wipe, zoom-blur, zoom-in-out. Custom presentations are a component receiving `presentationProgress` and `presentationDirection`.
- Quality judgement (ours, not the docs'): most of that list (ripple, dreamy-zoom, film-burn, book-flip, clock-wipe, crosswarp, light leaks) reads as template/"AI slop" on social. Default to hard cuts on the beat of the voiceover, with `fade`/`slide`/a custom push only where a cut would confuse the viewer.

### 5.3 `@remotion/motion-blur`

- Three options (https://www.remotion.dev/docs/motion-blur): `<HtmlInCanvasMotionBlur>` (4.0.529, "state-of-the-art"; `shutterAngle` 0-360 default 180, `samples` 1-64 default 8; preview needs Chrome 149+ with `chrome://flags/#canvas-draw-element`, "Rendering needs no configuration"); `<CameraMotionBlur>` (works without the flag, but "layered blending can change colors and opacity"); `<Trail>` (stylised echo, not realistic).
- Gotcha: `useCurrentFrame()` must be called INSIDE the blurred child, else no blur (https://www.remotion.dev/docs/motion-blur/common-mistake).
- Cost scales with `samples`. Use only on fast moves (a phone flying in, a quick pan), not globally.

### 5.4 Fonts (Geist, OFL)

- Geist and Geist Mono ARE available as `@remotion/google-fonts/Geist` and `@remotion/google-fonts/GeistMono` (module files exist in `@remotion/google-fonts@4.0.538` on unpkg, checked 2026-10-26). That path "automatically blocks rendering until the font is ready" but fetches from Google at render time.
- Preferred for a studio: **local woff2 via `@remotion/fonts`** `loadFont({family: 'Geist', url: staticFile('fonts/Geist-<w>.woff2'), weight: '<w>'})`, one call per weight, files committed to `public/fonts/` (OFL allows bundling). Deterministic, offline, same glyphs as skanyx.com (https://www.remotion.dev/docs/fonts, skills `local-fonts.md`).
- Load fonts in ONE module and gate measurement behind a `WaitForFonts` HOC that uses `useDelayRender()` (pattern from the Remotion Recorder, https://www.remotion.dev/docs/layout-utils/best-practices). Font flashes in renders come from text drawn before the font loads; measuring before load gives wrong sizes.
- Script coverage: our 14 locales include Ukrainian (Cyrillic), Turkish, Hungarian, Polish, Lithuanian, Romanian, Slovenian diacritics. Ship the full Latin Extended + Cyrillic subsets of Geist (check the woff2 actually contains Cyrillic; if not, a per-locale fallback face must be chosen deliberately, not left to the system font).

### 5.5 `@remotion/layout-utils` (long German strings)

- `measureText()`, `fitText({text, withinWidth, fontFamily, fontWeight, textTransform})` -> `{fontSize}` (cap it: `Math.min(fontSize, 84)`), `fillTextBox({maxBoxWidth, maxLines}).add({text,...}) -> {exceedsBox}`, and **`fitTextOnNLines({text, maxBoxWidth, maxLines, fontFamily, fontWeight, letterSpacing, textTransform, maxFontSize})` -> `{fontSize, lines}`** (4.0.313), the right tool for a headline that must stay on 2 lines in German (https://www.remotion.dev/docs/layout-utils/fit-text-on-n-lines).
- Rules: call only after fonts load; pass the same font props as the rendered element (incl. `letterSpacing`, `fontVariantNumeric`); use `outline` not `border` (box-sizing shrinks the box); `validateFontIsLoaded: true` throws if the fallback font was measured (default true from Remotion 5).
- Design rule for us: set a FLOOR font size per text role (e.g. headline never below ~64px at 1080 wide). If `fitTextOnNLines` wants smaller, the copy is too long: fail the variant build and send it back to the copywriter rather than rendering unreadable text.

### 5.6 Lottie and Three

- `@remotion/lottie` `<Lottie animationData>`: load JSON inside `delayRender()`/`continueRender()` (skills `lottie.md`). Fine for small icon animations (warning-light glyphs), and they play frame-synced.
- `@remotion/three`: `<ThreeCanvas width height>` mandatory; "Shaders, models etc MUST NOT animate by themselves"; `useFrame()` from R3F is forbidden; `<Sequence layout="none">` inside the canvas (skills `3d.md`). For WebGL in renders use `--gl=angle` / `Config.setChromiumOpenGlRenderer('angle')` (recommended on desktop in Remotion 4; default in Remotion 5; "Memory leaks are a known problem with `angle`... split up long renders") (https://www.remotion.dev/docs/gl-options). `@remotion/effects` (light leaks, LUTs, colour correction) are WebGL too and need the same flag. R3F 9.1.2+/three 0.171+ for React 19 (https://www.remotion.dev/docs/react-19).

### 5.7 What the docs flag as janky or cheap

- Anything not driven by `useCurrentFrame()`: CSS `transition`/`animation`, Tailwind `animate-*`, R3F `useFrame`, self-running Lottie/GIF players, `Math.random()` without a seed -> flicker or choppiness because frames render out of order in parallel tabs (https://www.remotion.dev/docs/flickering).
- Assets that Remotion cannot wait for: CSS `background-image` / `mask-image` -> flicker; use `<Img>` in an `<AbsoluteFill>` (https://www.remotion.dev/docs/troubleshooting/background-image).
- `<Html5Video>`: "not frame-perfect", many of them "can lead to stutters" (https://www.remotion.dev/docs/flickering).
- Fonts measured or painted before load; `fitText` before the font is ready.
- Linear `scale` interpolation (looks like it decelerates; use `perceptual-scale`).
- Text too small / too close to the edge for vertical video (skills `video-layout.md`: >= 84px headline, >= 44px support text, 80px side / 100px top-bottom safe margins at 1080 wide). Platform UI (TikTok/Reels caption + buttons) covers more than that at the bottom and right; the platform-specs research should give the real safe zones.
- Low-pixel-density text: "You will have a less sharp text if the video is displayed on a high-density display" (https://www.remotion.dev/docs/quality); see `--scale` in section 6.
- JPEG frame capture at quality 80 (the default) softens UI text and gradients; irrelevant when shared-memory capture is active (section 6).

## 6. Highest-quality render settings for social upload

Facts from the docs (all https://www.remotion.dev/docs/..., 2026-10-26):
- **Codecs:** `h264` (default), `h265`, `vp8`, `vp9`, `av1`, `prores` (`encoding`). H.265 browser compatibility "Very poor"; ProRes is large, no browser playback, hardware-accelerated on macOS.
- **CRF:** H.264 range 1-51, default **18**; H.265 0-51 default 23. "If you enable hardware acceleration, you cannot set a `crf`" (use `--video-bitrate`) (`encoding`, `quality`).
- **x264 preset:** `superfast` .. `placebo`, default `medium` (`options/x264-preset`).
- **Pixel format:** `yuv420p` (default), `yuva420p`, `yuv422p`, `yuv444p`, `yuv420p10le`, `yuv422p10le`, `yuv444p10le`, `yuva444p10le` (`options/pixel-format`). Social platforms expect 8-bit 4:2:0; anything else is re-encoded anyway.
- **Colour:** "Export your video in `bt709` for more accurate colors"; bt709 becomes the default in Remotion 5; "it is recommended to also use `png` as the image format to have accurate color transformations" (`quality`, `options/color-space`). Without it, Remotion 4 defaults to bt601 (`"bt601"` same as `"default"` since 4.0.424), which shifts colours on phones that assume bt709 for HD.
- **Shared-memory capture (4.0.534):** on Apple Silicon + macOS 15+, frames go to FFmpeg as uncompressed bitmaps; `imageFormat` and `jpegQuality` then "have no effect". Confirm with `--log=verbose` ("Remotion shared-memory capture uses ..."). Opt out with `--disable-shared-memory-capture` (`shared-memory-capture`). So on our Mac, JPEG-vs-PNG no longer costs quality; keep `--image-format=png` anyway for the fallback path and colour accuracy.
- **Parallel encoding** is default since 4.0.534 (+30-80 MB RAM at 1080p) (`parallel-encoding`).
- **Audio:** `--audio-codec` (aac default for mp4), `--audio-bitrate` default **320k**, `--sample-rate` default **48000** (4.0.448) (`options/audio-bitrate`, `options/sample-rate`).
- **Concurrency:** default "half of the CPU threads available"; number or percentage; tune with `npx remotion benchmark src/index.ts <ids> --concurrencies=...` (`renderer/render-media`, `cli/benchmark`).
- **Hardware acceleration:** `--hardware-acceleration if-possible|required` uses VideoToolbox on macOS for prores (4.0.228) and h264/h265 (4.0.236); no CRF then, bitrate instead (`hardware-acceleration`). Good for fast drafts, not for finals (VideoToolbox H.264 at a given bitrate is visibly worse than x264 at CRF, general encoder knowledge).
- **Scale:** `--scale` multiplies output dimensions, "a 1280x720px frame will become a 1920x1080px frame with a scale factor of 1.5" (`options/scale`).
- **GOP:** `--gop` sets max frames between keyframes (4.0.466); default lets the encoder decide (`options/gop`).
- **QA renders:** `npx remotion still <id> out.png --frame=N --props=...`; `npx remotion render <id> out/frames --frames=0,30,90 --image-format=png`; `--frames=0-89` for a range; `--every-nth-frame` exists (GIF only) (`cli/render`, skills `remotion-render`).

fps 30 vs 60 (our judgement): the composition fps is the render fps. 30 fps halves render time and matches what TikTok/Reels deliver to most viewers; 60 fps makes scrolling inside the phone recording and fast UI motion visibly smoother. Because all timing is written as `n * fps`, the choice is a flag. Recommendation: author at 30, record the simulator at 60 CFR, and A/B one hero video at 60 before deciding the default.

Proposed final-delivery command (one master per variant, uploaded to all four platforms):
```bash
npx remotion render Scenario out/p0420.de.mp4 \
  --props=variants/p0420.de.json \
  --codec=h264 --crf=16 --x264-preset=slow \
  --pixel-format=yuv420p --color-space=bt709 --image-format=png \
  --audio-codec=aac --audio-bitrate=320k --sample-rate=48000 \
  --concurrency=50% --log=verbose
```
- Optional archival master: `--codec=prores --prores-profile=hq` (ProRes 422 HQ, `.mov`) then derive platform files with ffmpeg; only worth it if a human editor will touch the output.
- Draft/preview renders: same command with `--hardware-acceleration=if-possible --video-bitrate=12M` (no CRF), or `--scale=0.5`.
- After render, ffprobe gate (ours): 1080x1920, `avg_frame_rate == r_frame_rate` (CFR), `yuv420p`, `color_primaries/transfer/space = bt709`, AAC 48 kHz, duration within 1 frame of expected, loudness measured with `loudnorm` print_format=json (the silence-detection rule already shows the command).

## 8. Real-world Claude Code + Remotion experience (2026 sources)

No systematic post-mortem exists; sources are blogs, several with a commercial angle (flagged). Consistent findings:

- **The code is not the hard part; taste and timing are.** Demo Editor (Wildan, 2026-10-23, sells a competing tool): a founder's 50-second launch video took "about 100 prompts", "roughly a week", ~30 iterations on a creative brief before any code; "claude code wrote every single line of TSX. that part is real"; early iterations "all looked like a powerpoint"; timing fixes take several rounds because "Claude writes frame numbers and springs without seeing the result"; regressions across "50+ scene changes", some builds rolled back. Fixes: written creative direction doc first (acts, VO script, per-scene environment, typography, palette), plan-before-code, iterate scene by scene, commit after every accepted scene, real footage instead of rebuilt UI. https://demoeditor.com/articles/remotion-claude-code-launch-video
- **Why it looks flat.** AutoAE (Keston Collins, 2026-10-07, sells templates): Remotion can only draw what a web page draws, so "lighting, materials, ... real 3D are missing unless you supply them"; models default to "a dark background, glowing headline, gradient blob, and pill-shaped buttons" and "fade and slide in with the same spring". Fixes: layered depth/parallax, a distinct easing per element type, real fonts loaded before render, real screenshots/footage, `npx remotion still` key-frame checks for overlaps and broken line breaks. https://autoae.online/blog/claude-remotion-videos-look-flat
- **Anti-template rules** in a community skill (kimny1143/claude-code-template `remotion`, 2026-06-03): avoid "identical spring configs for every element" and "spacing delays evenly"; vary transitions; asymmetric layouts; per-element physics (heavy mockups damping 20, light dots damping 8). https://claudemarketplaces.com/skills/kimny1143/claude-code-template/remotion
- **App-video specific rules** (skill `create-onboarding-video` by bidah, skills.cat, ~mid 2026): "Pieces of the UI, not the whole UI" (crop to the focal component on a tinted background, avoid full-screen tours); beats 90-240 frames at 30 fps; captions in a fixed top band, same spot every beat, no re-animation when text continues; "Cursor leads every tap" (straight-line moves, ripple only after arrival); never invent UI, stills required. Directly relevant to our "tap timeline JSON" plan: the timeline gives us exact tap points to place a touch indicator and to drive crop/zoom. https://skills.cat/skills/bidah/skill-set/create-onboarding-video
- **Process hygiene.** Tella (2026-10-12, sells screen recording): skills not visible if installed outside the project root or mid-session (restart); "Rendering is less forgiving of resources that only happen to be available in your browser session" (fonts, remote media, paths); inspect diffs, Claude may rename files/add deps; constrain prompts with duration, dimensions, fps, verbatim text, allowed asset paths, fonts, motion style, and what NOT to invent. https://www.tella.com/blog/how-to-use-remotion-agent-skills-with-claude-code
- **Frame math.** OpenReplay (2026-06-04): simultaneous animations are "almost always missing `from` offsets"; fps/duration mismatches between Root and components; linear interpolate looks robotic; renders are one Chromium screenshot per frame, so time scales with frames x complexity; read the code and scrub Studio instead of blind re-prompting. https://blog.openreplay.com/making-videos-claude-code-remotion/
- **Reference-driven generation.** Louise de Sadeleer (2026-04-21): give Claude a reference image (or ffmpeg-extracted frames from a reference clip, since it cannot watch video) with minimal instructions first, then iterate; simple layouts work, complex hand-drawn detail does not. https://louisedesadeleer.substack.com/p/how-i-make-custom-motion-graphics
- **Skill shadowing bug (official issue).** Claude Code resolves same-named skills personal > project, so a stale GLOBAL Remotion skill silently overrides the version-matched project copy; observed effect: the agent "did not start the Studio ... and it rendered an MP4 by default" (issue #11809, open, 2026-09-29, Claude Code 2.1.284 / Remotion 4.0.529). The getting-started page's agent prompt itself suggests a global install (`npx -y skills@latest add remotion-dev/skills -g -y`, https://www.remotion.dev/docs). `npx remotion skills add` installs per project into `.agents/skills` with `.claude/skills` symlinked (https://www.remotion.dev/docs/cli/skills). On this Mac, no global Remotion skill or plugin is installed today (checked `~/.claude/skills`, `~/.agents/skills`, `~/.claude/plugins/installed_plugins.json`). https://github.com/remotion-dev/remotion/issues/11809
- Another stale-skill bug fixed 2026-10-21: generated skills imported `<Audio>` from a stale `@remotion/sfx` path (issue #12439). Keep skills updated with `npx remotion upgrade` / `npx remotion skills update` in lockstep with the packages.

Synthesis for the studio's CLAUDE.md and review loop:
1. A per-video creative brief file (script, beats with target seconds, shot list mapping beats to recordings/B-roll, on-screen text per locale, mood) is an INPUT the agent may not improvise around.
2. Design tokens (type scale, colours, 3-4 named easings and durations, caption style, safe zones) live in one module; the agent composes from them and may not add new curves or colours ad hoc.
3. Every change -> render 5-8 key stills (`npx remotion render <id> out/qa --frames=<list> --image-format=png --props=...`) and LOOK at them (Claude can read PNGs), plus a contact sheet via ffmpeg `tile` for the whole video; for motion, a low-res draft render reviewed by a human.
4. Deterministic gates before "done": zod validation of props, text-fit floors per locale, ffprobe checks on output, caption/VO alignment check (last caption end <= audio end, no caption under 300 ms).
5. Commit per accepted scene; never let the agent touch more than one scene per iteration.

## Decisions for the studio

### D1. Runtime and scaffold
- Remotion **4.0.538** exactly (no caret), all `@remotion/*` on the same version; React 19.2.3, TypeScript 5.9.3, zod 4.5.4, mediabunny 1.62.0 (what `@remotion/studio@4.0.538` pins; `npx remotion add` resolves it; npm `latest` is 1.62.1, do not drift).
- Node: pin **22 LTS** in `.nvmrc` + `engines` (`^22.13.0`) for CI/reproducibility; Node 26 locally is expected to work post-#7420 but verify with one real render before relying on it.
- Scaffold: `npx create-video@latest --yes --blank --no-tailwind skanyx-studio` (outside any Git repo, `--yes` refuses inside one), `cd skanyx-studio && npm i && npx remotion skills add` (project-local `.agents/skills`, symlinked to `.claude/skills`). Never install Remotion skills globally (issue #11809). Do not install the deprecated Remotion MCP. The Claude Code plugin is optional; project-local skills are enough and version-matched.
- Keep template `remotion.config.ts` settings (`setRspack(true)`, `setDefaultPremountInSeconds(2)`, `setOverwriteOutput(true)`), add `Config.setVideoImageFormat('png')` and `Config.setChromiumOpenGlRenderer('angle')` (the latter only if we use WebGL effects). There is no `Config.setColorSpace()` in the config docs (checked 2026-10-26), so pass `--color-space=bt709` on the CLI and `colorSpace: 'bt709'` in `renderMedia()`.

### D2. Packages (all 4.0.538 unless noted)
Runtime: `remotion`, `@remotion/cli`, `@remotion/bundler`, `@remotion/renderer`, `@remotion/media`, `@remotion/media-utils`, `@remotion/captions`, `@remotion/fonts`, `@remotion/layout-utils`, `@remotion/transitions`, `@remotion/zod-types`, `zod@4.5.4`, `mediabunny@1.62.0`, `react@19.2.3`, `react-dom@19.2.3`.

Dev: `@remotion/eslint-config-flat`, `eslint@10`, `prettier`, `@types/react@19.2.7`, `@types/web`.
Do not use: `<OffthreadVideo>` / `<Html5Video>` directly, `@remotion/google-fonts` for Geist (use local files), `@remotion/whisper-web` / `@remotion/media-parser` / `@remotion/light-leaks` (deprecated at 5.0), Tailwind animation classes.

### D4. Composition model
- One template composition per aspect (`Scenario-9x16` 1080x1920 first), `schema` = zod object, `calculateMetadata` reads scene durations from props (computed by `build-vo.ts` from the ElevenLabs alignment), sets `fps` from props (30 default, 60 trial) and `defaultOutName`.
- Scenes in a `TransitionSeries` (hard cuts by default via plain `.Sequence` adjacency; `.Transition` only where justified, and subtract its length in metadata). Each scene owns its VO `<Audio>` + captions under the same boundary so trims move together.
- Studio-editability conventions from the skills (`Interactive.*`, inline `defaultProps`, inline caption arrays) are NOT followed for data; they are fine for one-off hero edits. Write this exception into the studio CLAUDE.md so the agent does not "fix" it back.

### D5. Media rules
- Every recording and B-roll clip passes `scripts/normalise-media.ts` (ffmpeg) before use: H.264 High, CFR (60 for recordings, 30 or 60 for B-roll), `yuv420p`, bt709 tags, `-g` short GOP, `+faststart`, no audio (recordings), visually lossless CRF. Reject HEVC/VFR inputs at the gate (`ffprobe` + Mediabunny `computeFrameRateMetrics().frameRateIsConstant`).
- `<Video disallowFallbackToOffthreadVideo objectFit="cover" muted .../>` everywhere; trims via `trimBefore`/`durationInFrames` in frames from the tap-timeline JSON (re-based to the normalised file's t=0).
- Fonts: local Geist woff2 via `@remotion/fonts`, loaded in `brand/fonts.ts`, measurement only inside `WaitForFonts`.
- Text fitting: `fitTextOnNLines` with per-role max size AND a min-size floor; floor breach = build error for that variant.

### D6. Captions
- VO captions from ElevenLabs TTS `alignment` (not `normalized_alignment`) via our converter -> `Caption[]` with leading spaces and `pageBreakAfter` at script breaks -> `createTikTokStyleCaptions({combineTokensWithinMilliseconds: ~1200, breakOnSilenceAfterMilliseconds: ~250})`. Own caption design (brand type, no stock green-highlight/black-stroke TikTok look), placed inside platform safe zones, `white-space: pre`.
- Human VO: ElevenLabs Forced Alignment with the known script; fallback whisper.cpp (`tokenLevelTimestamps: true`, `t_dtw`).
- Also export `.srt` per variant (`serializeSrt`) for platform caption upload.

### D7. Render settings
- Final: `--codec=h264 --crf=16 --x264-preset=slow --pixel-format=yuv420p --color-space=bt709 --image-format=png --audio-codec=aac --audio-bitrate=320k --sample-rate=48000 --concurrency=50%` (tune concurrency with `npx remotion benchmark`); confirm shared-memory capture in `--log=verbose`.
- Drafts: `--hardware-acceleration=if-possible --video-bitrate=12M` or `--scale=0.5`.
- QA: `npx remotion render <id> out/qa --frames=<beat-midpoints> --image-format=png --props=...` + ffmpeg contact sheet + ffprobe gates (resolution, CFR, pix_fmt, bt709 tags, AAC 48 kHz, duration, loudness).
- Batch: one `bundle()`, `openBrowser()` once, `selectComposition` + `renderMedia` per variant (same options as the CLI final, passed explicitly).

### D8. Motion
- Named tokens only: e.g. `enter` = `Easing.bezier(0.16, 1, 0.3, 1)` ~0.35 s, `move` = `Easing.spring({damping: 200})`, `exit` = ease-in ~0.2 s, `emphasis` = spring with tuned damping per mass (heavy phone frame damping ~20, small chips lighter). `output: 'perceptual-scale'` on all scale animations. Vary delays deliberately (not evenly spaced). No bouncy default `spring()`. Motion blur only on fast phone moves. Hard cuts on VO beats; no ripple/dreamy-zoom/film-burn/light-leak transitions.

### D9. License
- Confirm Skanyx's total headcount incl. contractors. <= 3: Free License, no action. >= 4: Company License; a human-in-Studio workflow is a $25/month Creators seat per person, a scripted batch renderer is plausibly "Automators" ($0.01/render, $100/month minimum). Decide before building `scripts/render.ts`; if unsure, email hi@remotion.dev.

## Uncertain / verify

1. **Node 26 renders end to end.** Fix #7420 is in (no `extract-zip` in `@remotion/renderer@4.0.538` deps) but I did not run a render. Do `npx remotion browser ensure && npx remotion render` once on Node 26.3 and once on Node 22; check that `node_modules/.remotion/chrome-headless-shell` contains the binary.
2. **iOS Simulator recording codec/VFR.** I assumed `xcrun simctl io <dev> recordVideo` defaults to HEVC and produces VFR output; verify in the simulator research (and whether `--codec=h264` exists in the current Xcode). Either way, the normalise step makes it moot.
3. **Shared-memory capture on this Mac.** Docs say Apple Silicon + macOS 15+; we are on macOS 27.0.1 (Darwin 27). Confirm the `Remotion shared-memory capture uses` log line actually appears.
4. **`@remotion/media` `<Video>` with 60 fps sources in a 30 fps composition** (frame picking/sampling): not explicitly documented; test visually on a fast scroll.
5. **ElevenLabs alignment vs. displayed text** when the script contains fault codes, numbers, currency (`€79.99`, `P0420`): whether `alignment.characters` exactly equals the input text with `apply_text_normalization` on/auto, per language. Test per locale; the ElevenLabs research file should own this.
6. **ElevenLabs Forced Alignment language coverage** for all 14 locales (lt, sl, uk, ro, hu, tr...): not stated on the API page.
7. **Geist woff2 glyph coverage** for Cyrillic (uk) and all Latin Extended diacritics (lt, ro, hu, tr, pl, sl). Check the actual font files before committing to Geist-only.
8. **License specifics:** the FAQ/terms on remotion.dev are the v5.0 terms ("take effect upon the release of Remotion 5.0"); the v4 terms page (remotion.pro/terms-4-0, Nov 2023) did not show its Free-License text in my fetch. LICENSE.md (current) says "up to 3 employees", the v5 FAQ says "up to 3 people" and counts contractors. Also unclear: whether a solo operator running `npx remotion render` from a local script counts as "automation" vs a Creators seat; the terms list the CLI as automation but also say purely local use needs no Renders.
9. **`--license-key` / `--is-production` availability:** CLI docs label them 4.0.539 (unreleased as of 2026-10-26) while option pages say 4.0.409. Irrelevant on the Free License.
10. **WebMCP for Claude Code:** docs say only Codex supports it today; re-check later, since agent-driven Studio inspection (seek, read error overlay, element geometry) would be a strong review tool.
11. **HTML-in-canvas motion blur preview** needs Chrome 149+ with a flag; the render path "needs no configuration" per docs, not tested.
12. **Remotion 5.0 timing:** many defaults flip at 5.0 (bt709, `angle` GL, `validateFontIsLoaded: true`, mandatory telemetry for Company License, `inputProps` required in `selectComposition`, several packages unpublished). No release date found; pin 4.0.538 and upgrade deliberately with `/remotion-upgrade`.
13. **Platform safe zones and upload specs** (TikTok/Reels/Shorts/Facebook): not Remotion's domain; the skills' 80/100px margins are far smaller than the platform UI overlays. Take numbers from the platform-specs research.
14. **Social re-encode behaviour** (whether uploading CRF 16 vs a higher-bitrate master changes delivered quality per platform): general practice says upload the highest-quality H.264 the platform accepts; not verified here.
